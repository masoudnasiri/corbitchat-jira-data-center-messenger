## Highlights

Two headline additions since the previous internal cut, plus a batch
of chat polish and hardening fixes.

1. **Board Gallery** — a visual card directory of every Jira board
   the current user can access, added to the Jira top navigation.
2. **Reply to Jira comments** — a new *Reply* action on every issue
   comment that opens an inline composer, auto-mentions the parent
   author, quotes the parent, submits as a real native Jira comment,
   and now supports **file attachments** with drag-and-drop.

Both features live in dedicated web-resources so they never touch
Jira core or the CorbitChat messaging pipeline.

## 1. Board Gallery

A new top-nav entry **Board Gallery** (`/plugins/servlet/jim/boards`)
that lists every Jira board the current user can see, rendered as
visual cards.

### For end users

* Each card shows:
    * Board name, board type (Scrum / Kanban), board id.
    * Real Jira **project avatar** and project name (clickable — opens
      the project page).
    * **Project lead** name.
    * **My tasks** count (issues assigned to me in this project's
      board context) — clickable, opens the filtered Jira issue
      list.
    * **All project tasks** link — clickable, opens the project's
      unfiltered issue list.
    * **Project chat** link — clickable, opens the CorbitChat
      project chat for that project.
* Fast client-side **search** + **filter tabs** (All / Scrum /
  Kanban).
* A page-level **Open Chat** button (top-right) to jump to the main
  CorbitChat page in one click.
* Empty state, error state, and long-name handling all covered.

### For operators

* Server-rendered Velocity template `templates/board-gallery.vm`;
  data fetched entirely from Jira REST (`/rest/agile/1.0/board`,
  `/rest/api/2/project`, `/rest/api/2/search`).
* Only boards / projects / issues the current Jira user can access
  are returned — native permissions are respected in full.
* Same-origin URL rewriting: project avatars from
  `https://jira.corbitlogic.com/secure/projectavatar?…` are stripped
  to their `path + query` form so they resolve against the current
  browser origin (fixes cross-origin image blocking on non-canonical
  hosts, e.g. IP-based test access).

### How to reach it

Top navigation bar → **Board Gallery**.

## 2. Reply to Jira comments

A new lightweight reply action on every native Jira comment.

### For end users

1. Open any Jira issue and hover an existing comment.
2. Click the new **Reply** link at the front of the comment's action
   toolbar (before *Edit · Delete · Pin · 🙂*).
3. An inline composer opens directly below that comment showing:
    * `↳ Replying to <Author>` header with a ✕ to cancel.
    * A quoted preview of the parent comment.
    * An autofocused textarea.
    * **Attach** button (paperclip) + drag-and-drop for files.
    * Cancel and **Send Reply** buttons.
4. Type your reply, attach one or more files (chips appear with a
   file icon, filename, and per-file "(uploading…)" status).
5. Click **Send Reply** or press **Ctrl/Cmd+Enter**. **Esc** cancels.

After you send, in-place update — no page reload:

* The composer is replaced *in place* by the new comment (fades in
  with a brief blue highlight, auto-scrolled into view).
* The new comment shows an "↳ **In reply to** *Author*" badge above
  its body.
* Images in the reply render as native Jira inline thumbnails,
  other files render as clickable Jira attachment links (the same
  representation you'd get from the native comment editor).

### Behind the scenes

Because the saved reply is a **real native Jira comment** (posted to
`POST /rest/api/2/issue/<key>/comment`), everything native "just
works":

* The `[~username]` token is a Jira-recognized mention → Jira's
  built-in mention notification is dispatched to the parent author
  automatically (email + in-app, subject to their notification
  settings).
* CorbitChat's existing `CommentCreatedEvent` listener picks up the
  same comment and posts a **Jira Assistant** entry to the mentioned
  user's bot conversation (issue key, actor, preview, link) — so
  the reply also lands in their chat sidebar.
* Native Jira permissions, comment visibility, edit / delete rules
  and audit trail apply unchanged.
* The reply relationship persists in Jira's own data model — the
  `[~mention]` + `{quote}…{quote}` block live inside the comment
  body, so it's visible after refresh, when the issue is reopened
  later, in mobile, in exports.

### Attachment lifecycle

* Files upload immediately to `POST /rest/api/2/issue/<key>/attachments`
  when picked (so success / failure is visible per file before the
  user submits).
* Successful submit keeps the attachments (they're referenced from
  the saved comment).
* Cancel / Escape / ✕ / removing a chip DELETEs any orphaned
  uploads (`/rest/api/2/attachment/<id>`) — no stray files left
  behind.

### Edge cases handled

| Case | Handling |
|---|---|
| Reply to your own comment | `[~mention]` is suppressed (no needless self-notification); the `{quote}` is still inserted. |
| Parent comment author is inactive / deleted | Existing `JimMentionParser` skips them; no Assistant noise. |
| Restricted / permission-scoped parent comment | Native Jira permissions apply to the reply itself; the Assistant entry is gated by the same visibility checks. |
| Long parent comment | Truncated to 240 chars with an ellipsis in the quote. |
| Multiple replies to one parent | Each creates its own native comment with its own `[~mention]` + quote + badge. |
| Many comments on the issue | A `MutationObserver` on `#issue_actions_container` attaches the Reply link per-comment as Jira renders them — no eager full-DOM scan. |
| Jira issue-view variants | Reply link works on `/browse/<KEY>`, `/projects/<PROJ>/issues/?selectedIssue=<KEY>`, `/issues/?selectedIssue=<KEY>`, and Agile-board side-panel views. Issue key is resolved from **6 fallback sources** including the parent comment's own DOM. |
| Service Desk / SSO surfaces | Author resolver has 5 fallback strategies (`user-hover[rel]` → `[data-username]` → `?name=` in `ViewProfile.jspa` href → any non-junk `rel` → last-resort display name); button still injects even if the author is unresolvable (composer just opens without auto-mention). |
| Slow / broken activity feed | Periodic tapered backstop scan (750 ms for 30 s, then 5 s for 4.5 min) + AJS `ajaxStop` + `JIRA.Events.NEW_CONTENT_ADDED` hooks. |

### Operator self-diagnostic

If a user reports the Reply link is missing on a specific Jira
surface, paste in DevTools console:

```js
window.JimCommentReply.diagnose()
```

Returns version, comment counts, button counts, issue-context
resolution status, and the AJS / JIRA hook availability. Verbose
per-event logging can be toggled with:

```js
window.JimCommentReply.enableDebug();   // persists in localStorage
window.JimCommentReply.disableDebug();
```

## Chat polish delivered in this release line

Not new headline features on their own, but improvements that all
sit under the same operational JAR bump.

### Edit message — pro-messenger UX

Editing your own message no longer opens a cramped inline form
inside the bubble. Instead:

* Message body loads into the **main composer** at the bottom.
* An amber **"Editing message — Esc to cancel"** chip appears above
  the composer with a one-line preview.
* The bubble shows an italic "*Editing this message…*" placeholder.
* Send button label changes to **Save** (amber accent).
* **Esc** cancels and restores whatever draft you had typed before
  clicking Edit — your in-progress text is never destroyed.
* Reply / issue-link / file / voice / conversation-switch all
  cleanly exit edit mode.
* Server-side 30-minute edit window still enforced.

### Group / project chat — real sender avatars

Every message bubble in a group or project chat now shows the
**sender's real Jira avatar** instead of coloured initials.

Root cause was a missing `senderAvatarUrl` field on the message
JSON plus a wrong fallback in the JS that used the *conversation*
avatar for every bubble (which is meaningful only in a 1-on-1
chat). Both halves fixed; direct-chat behaviour unchanged.

### Persian (non-ASCII) filenames on download

Downloading an attachment whose original filename contains
Persian, Arabic, CJK, or accented Latin characters now preserves
the original filename. Was: browser saved as literal `download`
or `?`. Now: `Content-Disposition` emits both an ASCII fallback
and the RFC 5987 `filename*=UTF-8''<percent-encoded>` form.

Verified live: uploading `فایل_تست.txt` and downloading it back
returned:

```
Content-Disposition: attachment;
    filename="________.txt";
    filename*=UTF-8''%D9%81%D8%A7%DB%8C%D9%84_%D8%AA%D8%B3%D8%AA.txt
```

### Project chat parity

The project chat panel and the main chat page share the **same
Velocity template, the same JS, and the same CSS**. Every chat
improvement above (and every earlier one — drafts, lazy-load
older messages, per-bubble timestamps, 5000-char message split,
sender-coloured previews, multi-select mention picker, drag/drop
attachments, voice messages) is automatically available in the
project chat panel too. Verified by fetching
`/projects/<KEY>?selectedItem=…:jim-project-chat-link` and
inspecting the rendered DOM.

## Compatibility & rollback

* **Compatible with:** Jira Data Center 9.x (tested against
  9.17.5).
* **Requires:** the same VAPID / attachment-storage configuration
  as prior 1.0.0-internal builds. No new admin steps.
* **AO schema:** unchanged. The `senderAvatarUrl` change is
  runtime-only (added to the message JSON, not stored). No
  migration.
* **REST surface:** additive only. `senderAvatarUrl` is a new
  field on message payloads; existing consumers ignore it safely.
* **Rollback:** replace the JAR with any prior release from
  `/root/jira-dev/releases/`, restart Jira. No DB fix-up needed.
* **Marketplace licensing:** intentionally disabled (this is the
  `internal-corbit` distribution).

## Installation

1. Copy `corbitchat-jira-dc-1.0.0-internal-reply-attach.jar` into
   `<jira-home>/plugins/installed-plugins/`.
2. Restart Jira (or hot-swap via UPM if preferred).
3. Verify:
    * `GET /rest/jim/1.0/health` → 200
    * `GET /rest/jim/1.0/admin/diagnostics` reports
      `pluginVersion = 1.0.0-internal-reply-attach`
4. Users: hard-refresh (`Ctrl+Shift+R`) on any open chat / issue
   tabs so the WRM context batch loads the new JS.

## Known limits

* The inline reply composer supports **attachments** but does not
  replicate Jira's full wiki-editor toolbar (Bold / Italic / Link /
  Lists / emoji picker / Visual↔Text toggle). Wiki syntax typed
  directly (`*bold*`, `_em_`, `[link|http://…]`) works as normal.
* Board Gallery reads Jira's board + project + issue APIs; if any
  of those responses are slow, the initial paint may take a few
  seconds on very large instances (subsequent loads are cached).
* Server-Side Includes / Jira's own progressive-enhancement custom
  elements (`<jira-comment-pins>`, `<jira-comment-reactions>`) are
  intentionally NOT re-rendered on our in-place inserted reply
  comment; they return on the next natural page refresh. Reply /
  Edit / Delete on the inserted comment work immediately.
